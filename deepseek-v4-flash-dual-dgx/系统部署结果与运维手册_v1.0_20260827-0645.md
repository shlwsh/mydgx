## 9. 安全与注意

1. **内存余量**：128K 配置下 available 偏低（Node0 ~7-9GiB，Node1 ~4GiB），注意监控
2. **HTTPS 自签名**：opencode 无法信任（Bun），故客户端走 HTTP :4000；HTTPS :4443 需 `-k`/`verify=False`
3. **NIM 已清除**：如需回滚需重新从 NGC 下载（注意网络限速窗口）
4. **Node 0 内存告警历史**：曾整机无响应（113Gi 占用时），避免叠加高内存任务
5. **代理时效**：Clash/FlClash 节点会失效，`pkill verge-mihomo` 恢复
6. **端口占用**：Portainer 勿再映射 8000（已处理）；勿让其他服务占 18090/4000/4443

## 10. 快速故障排查

| 症状 | 排查 |
|---|---|
| 网关 401/无响应 | `sudo systemctl status litellm`；key 是否 `sk-dgx-local-2026` |
| vLLM 无响应 | `curl :18090/health`；`docker logs deepseek-v4-flash-0731-0 --tail 50` |
| 推理慢/卡 | 检查内存 `free -h`；是否 NIM 又拉起（应 `docker update --restart=no`） |
| 网络不通 | `ip route get 192.168.100.11`；`ethtool enp1s0f0np0`；`ibdev2netdev` |
| vLLM 起不来，日志 `ibv_modify_qp failed ... local GID ::` | **GID 表漂移**：核对 `/sys/class/infiniband/rocep1s0f0/ports/1/gids/3`（应非空）；当前 RoCEv2 IPv4 GID 在 index 4，需改双机 `.env` 的 `IB_GID_INDEX`，详见 `reports/incident-20260902-vllm-roce-gid.md` |
| 请求 400「输入过长…超过上下文上限 125000」 | **预期策略**：LiteLLM 硬顶 125K，`input>125000` 一律拒绝且不进后端；请压缩历史/开新会话（`litellm_hooks.py` 的 `HARD_INPUT_LIMIT`） |
| `:18090` 外部直连不通 | **预期策略**：已做仅本机收敛（`vllm-port-lockdown.service`，iptables 回环 ACCEPT/其余 REJECT），外部一律走网关 :4000/:4443 |
| vLLM 容器异常退出（state=Exited） | 会自动自愈：Node0 `vllm-watchdog.timer`（60s）先重启 Node1 再 Node0，约 3 分钟恢复；日志 `~/logs/vllm-watchdog.log`。人工维护请先 `touch ~/.vllm_maintenance` |
| 证书失效 | 重新生成证书 + `sudo systemctl restart litellm-https` |
