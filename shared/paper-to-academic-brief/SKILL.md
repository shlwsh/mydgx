# Goal

让读者先快速看清每条核心主张和实证结论，需要时再核查数字、来源和推断边界。

## Instructions

1. **先找准输入。** 以用户指定的论文版本、受众、篇幅和输出位置为准。用户说「当前主稿」时，查项目入口和交付记录。用可用的 PDF、文档、网页或同版源文件定位正文、图表、公式、附录和引文。有正式交付稿时，用它核对成文版本。补充材料、原始数据和旧稿只用于核查其各自对应的论证。来源冲突时，记录冲突及影响，采用有依据的版本。只有摘要、节选或缺失材料时，明确成文能覆盖的范围。
2. **从结论反查证据。** 先读摘要、贡献、结果与局限。将同一贡献的不同表述合并，按问题组织主张。再给每条主张找回假设、指标、比较对象、关键发现和适用范围。以结果和方法为准判断说法能有多强。理论主张用命题及假设，实证主张用已做的比较，定性研究用材料、分析方法和反例。作者没给出的假设或机制归因标明是推论。
3. **先建数字台账，再写正文。** 按[数字台账流程](references/number-ledger.md)独立清点原稿，生成 JSON 中间文件。逐次登记数字的原文位置、含义和对应主张，写完后补上简报里的原样引句和数值落点。默认清点原稿全部数字。用户明确选定部分章节或只要重点数字时，把覆盖范围写清。正文先讲会改变结论的数，余数放在相应主张下的小表、简短细节或来源说明，保留数值、符号、精度、单位、分母、方向、权重及端点。派生数另标计算依据。语义和口径完全相同的重复引用可以指向同一个落点。只有数值相同的条目各自使用独立落点。
4. **分清对比、消融和其他证据。** 对比先说清基线、场景、样本或重复、共享条件及差距。把效果量与显著性、实际意义和不确定性分别交代。消融要指出单独改变了什么、哪些条件保持一致、指标怎么变。多个组件同时变化的结果只能说明组合效果。算例、参数推算、回放、日志反例、模拟、先导与真实测量保留各自口径。去掉组件的正式测量缺席时，说明能找到的线索回答了哪个问题，以及哪项贡献仍没有量化。遇到持平、反向结果和强基线，保留它们并解释对适用范围的影响。
5. **解释引文在论证里做什么。** 每条主张引入相关研究做法及其作用，例如给出定义、支持假设、提供比较方法，或展示一个已有结果。数字来自外部文献时，紧跟它的样本、环境与原文定位。只有论文转述时注明「主稿援引」，待原文可用再核对。背景文献的方法可以为判断提供依据，本研究的效果量由本研究数据支撑。
6. **核查数字能否支撑结论。** 遇到「合理性、矛盾、虚拟数字、追溯」等要求，用[数字证据核查](references/numeric-review.md)比较摘要、正文、图表、结论和可用归档。优先只读复算对结论敏感的数字。原值、复算值和影响并列写。算例、代理指标、正式观测和暂缺来源分别如实标注。无法追溯时，记录查过的来源和剩余缺口。台账条目可填 `evidence_type` / `check_status` / `basis`；`python3 scripts/number_ledger.py review 数字对照.json` 汇总冲突与待追溯项，供速读短表引用。
7. **让主张可以速读，数字可以细查。** 开头用短段说明所有核心主张。紧随一张「对结论有影响」的数字核查短表（原值｜复算｜影响）。每项先讲发现，再用最能说明问题的对比、消融或证据缺口交代结论及用途。默认按「主张说明 → 假设或适用条件 → 实证与文献 → 结论和学术价值」推进，可合并相邻要点。逐项明细放在就近折叠区或明确链接的简报附件。交付格式按用户要求和项目约定。交付前运行台账检查，按[成文模板](references/brief-template.md)人工核对语义。缺页、图表读数不清和未映射的数字保留待核位置。

## Examples

- 输入「把材料实验的主张写成一段简报，并说明配方对比与去组分实验」。输出在同一主张下写出基线差、单组件差、引文的用途和适用条件。见[有实测消融的样例](examples/01-measured-ablation.md)。
- 输入「把教育干预论文全稿数字整理到各主张下，交代消融」。原稿只有组合干预及基线时，说明组合效果和可核查数字，交代单项归因的证据缺口。见[缺少消融的样例](examples/02-missing-ablation.md)。

## Constraints

- 保留源材料的事实、口径和证据强度。计算时能复查输入与推导，改动与论文不同的数值时写明依据，存疑处可定位。
- 摘要整理和文献介绍按授权范围进行。需要新增实验、外部检索或额外审计时，依据用户任务和可用来源决定。
- 技能目录可直接复制或引用。配套文件使用目录内相对路径。正文语言、文档名、展示形式和交付路径随任务而定。
