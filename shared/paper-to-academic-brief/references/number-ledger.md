# 数字台账流程

台账把论文原文的每处数字和简报中的具体用法接起来。先独立盘点原稿，再使用台账写简报。默认扫完全部主稿，用户指定摘录范围时只统计选定部分并注明范围。

## 1. 固定用于对照的原文

- 记录采用的稿件名、版本和范围。有可读的 UTF-8 原稿时可直接使用。PDF、Word 或扫描件先导出 UTF-8 文本作为对照快照。例如有 Poppler 时，可用 `pdftotext -layout 论文.pdf 原稿快照.txt`。扫描件可转录或 OCR。根据原页核对图表遗漏、错列、模糊字符和公式中的指数、负号、小数点。扫描前把漏掉的图中文字和表格数字按原样补入快照，保留实际页、图和表坐标供登记。
- 核查摘要、正文、方法、图表单元及标签、公式和算例、附录、脚注及参考文献。数字包括实验值、分母、参数、阈值和定位信息。论文援引外部文献时，登记主稿实际引用的数值。从原文进一步取数属于补充证据，单独写出处。
- 默认将台账和简报放在同一交付位置。原文需要转换时，同时保留用于校验的文本快照。目录、文件名及中间文件归档遵循目标项目的约定。

## 2. 生成台账并补全场景

从技能目录运行，也可将脚本路径换成实际安装位置。脚本使用 Python 3 标准库。

```sh
python3 scripts/number_ledger.py init 原稿快照.txt 数字对照.json --scope '定稿 v2，正文与附录'
```

命令逐处登记阿拉伯数字候选，含常见小数、符号、百分号、科学计数法及 Unicode 上下标。每条带原文字面、行列和 ID，文件记有稿件范围和快照 SHA-256。按实际范围填写 `--scope`。文本有改动时重新确认快照并按新版建台账。

逐条补 `locator`（稿件、页/节、图表行列、引文编号等）、`meaning`（指标、条件、单位、口径）和 `claim`（简报主张名或书目、来源说明）。页码、年份、版次、日期和识别号可归到相应的来源说明。对源文中拼写为文字的数量或罗马数字，按原文字面、行、列补录独立条目。用 Unicode 字符计数，从 1 起填行列。语义一致的重复数字各留一行，后续可用 `alias_of` 指回主条目。等值但场景、指标或口径不同的数字保持独立。

## 3. 把每条记录连到成稿

- 为每个主条目填写 `use.quote`（可读正文中的精确引句或表格行，全文唯一）和 `use.text`（该引句中对应的数字字面）。必要时用 `use.occurrence` 指向引句中该字面从左到右第几处，从 1 起。引句应带有足够上下文，能看出对应的对象和单位。正文中的 Markdown 标记也按原样引用。
- 真正的重复出现用 `alias_of` 指向主条目的 ID，保留各自的来源坐标，令 `use` 为 `null`。别名的字面、含义和主张与主条目一致。不同条目各自有精确落点。新增计算出的数字保留原始数值并写明公式和输入。
- 原稿中的数字精度、符号、单位及限定语随数字保留。脚本认可普通减号与数学减号、半角与全角等字形差异。中文或英文拼写数量转成不同字面时，在补录条目的 `use.equivalence` 中说明对应关系。舍入值或单位换算作为另列的派生值，保留原稿数值作对照。

一项示例。省略了文件外层和其他条目。

```json
{
  "id": "N0007",
  "line": 28,
  "column": 12,
  "text": "−13.54%",
  "locator": "定稿第 9 页，表 2，重压等权行，相对静态列",
  "meaning": "重压等权负载相对静态对照的变化率",
  "claim": "重压下累计隔离负载更低",
  "use": {
    "quote": "| 重压等权 | 相对静态 −13.54% |",
    "text": "−13.54%"
  }
}
```

## 4. 从原稿、台账和简报一起验收

```sh
python3 scripts/number_ledger.py check 原稿快照.txt 数字对照.json 学术简报.md
```

脚本检查快照哈希、扫描候选覆盖、源文字面、唯一落点、数值字面及重复引用规则。脚本只校验文本，表格行列、单位、分母、脚注和书目语义仍应对照原页逐项抽取和核查。确认每个落点在读者能看到的正文、表格或出处中。同值的条目还要确认与各自的场景和指标相符。有意省略或原页不可读的范围须记录下来，保留未完成的映射和实际原因。

有数字合理性要求时，按[数字证据核查](numeric-review.md)在条目上补 `evidence_type`、`check_status`、`basis`。三者要么都空（仅字面映射），要么都填；脚本在 `check` 时校验枚举，并打印 `REVIEW` 汇总。单独查看：

```sh
python3 scripts/number_ledger.py review 数字对照.json
```

`review` 发现已登记的冲突时退出 2，可据此提醒读者；`check` 的结果仍独立反映数值映射是否完整。冲突或待追溯的关键数字应在速读段列出原值、复算与影响。若各落点都在同一数字附录，`check` 可直接核对该附录。落点分布在多份文件时，可在核验前拼接实际交付的文本，并在台账注明引用所在文件。

若命令失败，先查看报出的条目或坐标，检查原文、台账和简报的对应关系。脚本异常时阅读脚本并修复实际故障。交付时分别报原稿数字出现次数、独立用法和重复引用数。快照覆盖已人工复核，且映射校验通过后，才报告已完整覆盖。

## 5. 负例自检

在技能目录运行：

```sh
python3 scripts/test_number_ledger_negatives.py
```

覆盖：合法映射通过；遗漏原稿数字失败；改值失败；同值不同主张抢同一简报落点失败；`alias_of` 重复引用通过。
