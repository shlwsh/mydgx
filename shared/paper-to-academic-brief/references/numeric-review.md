# 数字证据核查

用于核查论文数字之间的矛盾、合理性、来源和证据强度。把实际查过的来源、方法和结论范围写入简报。

## 从结论回到数字

1. **明确数字的性质。** 登记实测原始记录、观测推导出的指标、按假设计算的算例、模拟或代理结果、配置及外部文献等各自的来源和范围。例如「名义请求速率 × 实测时长」衡量的是按名义需求计算的暴露，实际放行计数有自己的分母。
2. **统一口径后再比较。** 对照同一结论的摘要、正文、表图和结论，先核对版本、比较方向、组别、样本与重复、单位、计量时段、过滤规则、权重和精度。来自不同端点的数字放回各自语境。表注或文字说错口径时保留原值和定位，再写清正确解释。
3. **复算会改变结论的数字。** 有原始事件或分组表时，用只读复算入口或直接对照小表，记录公式、输入、输出和有效位数。从精确输入复算后再按原稿精度舍入。分开均值之比与逐组相对差的均值、绝对差与百分点、零记录与缺失记录。核对报告样本量与归档分母。统计量还要核对检验方向、预设阈值和样本量下可达到的最小 p 值。
4. **描述可验证的发现。** 按「原稿位置及数值 → 核查依据与复算值 → 对主张的影响」记录。区分可复算一致、已解释的口径差异、定义与数值冲突、尚未追溯、推断超出证据。校验器只证明登记和文本对应。来源缺失或有矛盾时写出可验证的事实，认定伪造还需独立证据。

例如两个配对组的基线为 10、90，处理后为 5、81。逐组降幅是 50%、10%，平均为 30%。先合计再比较则是 14%。如果表注声称用合计口径却写 30%，表注明示的估计量与表值冲突。两种计算都能从同一组原始数推得。

## 让简报可以速读

正文呈现核心主张、最能改变判断的数字和影响解读的疑点。用小标题或链接把其余数字与[数字台账](number-ledger.md)接上。可在 JSON 条目追加这些字段供查阅。

| 字段 | 内容 |
| --- | --- |
| `evidence_type` | 原始观测 `raw_observation`、派生估计 `derived_estimate`、模型算例 `model_example`、代理观察 `proxy_observation`、配置 `configuration` 或书目 `bibliographic` |
| `check_status` | 一致 `consistent`、口径差异 `scope_difference`、冲突 `conflict`、待追溯 `pending_trace`，或仅确认字面 `literal_only` |
| `basis` | 上游数据、方法、复算值和影响。未追溯时记录已查过的材料。 |

保留原稿值及其成稿落点。复算修正和原值并列，读者可以查清论文究竟写了什么。
