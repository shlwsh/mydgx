# 工作站桌面图标与启动器修复方案 v1.0

适用主机：本机工作站 `cube-fe5e`（NODE123，Ubuntu + GNOME 46，X11）
适用场景：Dock（收藏）/ 应用面板 / 桌面快捷方式上的应用**图标不显示、显示灰色通用图标、或应用在面板里找不到**。

## 一、结论速览

这类现象在本机归结为 **三类根因**，外观相似但处理方式完全不同：

| 类型 | 典型现象 | 根因 | 修复动作 |
|---|---|---|---|
| A. 图标名查不到 | Dock 上是灰色方块/齿轮，但 PNG 文件确实存在 | 图标只放在 `hicolor` **未登记**的尺寸目录（本机未登记 `1024x1024`），图标主题索引不到 | 生成 512/256/128/64/48/32 多尺寸并刷新缓存 |
| B. 窗口关联失败 | 应用运行时 Dock 上是灰色齿轮，名称也拿不到 | 窗口 `WM_CLASS` 与桌面项 ID 不一致，且桌面项未声明 `StartupWMClass` | 在用户级覆盖项补 `StartupWMClass` |
| C. 面板里看不到 | Dock 上有图标，应用面板（Show Applications）里翻不到 | GNOME 有意把 `favorite-apps`（Dock 收藏）排除出应用面板 | 属设计行为；如需在面板显示则取消收藏 |

另有 D 类小问题：桌面项 `Name=` 为空、`Version=` 误填应用版本号（应为 desktop 规范版本），会导致无显示名、校验报错，修复脚本一并处理。

## 二、机制说明

### 2.1 桌面项查找顺序

`~/.local/share/applications`（用户级，优先级高）→ `/usr/share/applications`（系统级）。
同名 ID 时用户级覆盖系统级，因此**修复优先写用户级覆盖项**，厂商升级覆盖系统文件后修复依然有效。

### 2.2 图标主题如何查找图标

`Icon=` 可以是绝对路径（直接用），也可以是**图标名**（交给图标主题查找）。图标主题按 `index.theme` 的 `Directories` 列表决定哪些目录可见：

```bash
# 本机 hicolor 是否登记 1024x1024：结果为 0 表示未登记，放 1024 图标等于没放
grep -c "1024x1024" /usr/share/icons/hicolor/index.theme
```

`/usr/share/icons/hicolor/icon-theme.cache` 是缓存，**新增/替换图标后必须刷新**，否则 Dock 继续显示旧图标：

```bash
sudo gtk-update-icon-cache -f -t /usr/share/icons/hicolor
```

### 2.3 运行窗口如何关联桌面项

GNOME（`shell-window-tracker`）依次尝试：

1. 桌面项的 `StartupWMClass` 与窗口 `WM_CLASS` 的 **class 段**（第二个值，大小写不敏感）比对；
2. 桌面项 ID（去掉 `.desktop`）与 `WM_CLASS` 比对。

两者都不匹配 → 窗口变成“无桌面项的后台窗口”，Dock 只能给通用图标，也拿不到应用名。

一个应用可能有多个窗口且 `WM_CLASS` 不同（Electron 常见）：

```text
antigravity ide / Antigravity IDE   ← 主窗口（需要 StartupWMClass 指向它）
antigravity-ide / Antigravity-ide   ← 辅助窗口（靠 ID 匹配即可）
```

### 2.4 应用面板为什么排除 Dock 收藏

GNOME Shell 源码（Ubuntu 打包在 `/usr/lib/gnome-shell/libshell-14.so` 的资源里）：

```bash
gresource extract /usr/lib/gnome-shell/libshell-14.so /org/gnome/shell/ui/appDisplay.js \
  | grep -B2 -A3 "_appFavorites.isFavorite"
```

```js
return !this._appFavorites.isFavorite(appInfo.get_id()) && ...
```

即：**已在 Dock 收藏的应用不再出现在应用面板**，这是设计行为。概览搜索仍能命中并启动。

## 三、诊断流程（按顺序执行）

### 步骤 1：一键自检

```bash
cd /home/bot/work/mydgx
.venv/bin/python scripts/check_desktop_integration.py            # 收藏图标 + 窗口关联
.venv/bin/python scripts/check_desktop_integration.py --favorites # 只看 Dock 收藏
.venv/bin/python scripts/check_desktop_integration.py --windows   # 只看运行窗口
```

输出示例：

```text
✅ antigravity-ide.desktop（Antigravity IDE）
...
全部 11 个收藏应用图标与桌面项正常
所有运行窗口都能关联到桌面项
```

异常输出说明：

- `❌ xxx.desktop：图标名 xxx 在尺寸 [16, 24] 查不到` → 类型 A，见 4.1
- `⚠️ 窗口无法关联桌面项：WM_CLASS=xxx` → 类型 B，见 4.2
- `❌ xxx.desktop：桌面项缺失` → 应用被卸载或 desktop 文件被删

> 脚本需要 PyGObject，只装在系统 Python 中；用 `.venv/bin/python` 运行时会自动切换到 `/usr/bin/python3`，无需手工处理。

`ding@rastersoft.com`（桌面图标扩展）的 `gjs` 窗口本身没有桌面项，脚本已将其列入忽略名单，不算异常。

### 步骤 2：定位桌面项

```bash
ls ~/.local/share/applications | grep -i <应用名>
ls /usr/share/applications | grep -i <应用名>
python3 -c "from gi.repository import Gio; print([a.get_id() for a in Gio.AppInfo.get_all() if '关键词' in a.get_id()])"
```

### 步骤 3：验证图标能否被主题解析

```bash
python3 - <<'EOF'
import gi
gi.require_version("Gtk", "3.0")
from gi.repository import Gtk
theme = Gtk.IconTheme.get_default()
for name in ("antigravity-ide", "yunshu"):
    info = theme.lookup_icon(name, 64, 0)
    print(f"{name}: {info.get_filename() if info else '❌ 未找到'}")
EOF
```

`Icon=` 是绝对路径时，直接检查文件是否存在且能解码：

```bash
file /usr/share/icons/hicolor/scalable/apps/yunshu.png
python3 -c "from PIL import Image; print(Image.open('/path/to/icon.png').size)"
```

### 步骤 4：检查窗口关联

```bash
wid=$(xdotool search --name "窗口标题关键词" | head -1)
xprop -id "$wid" WM_CLASS _NET_WM_NAME
```

把输出的 **class 段**（第二个值）与桌面项 ID / `StartupWMClass` 对照。

### 步骤 5：确认是否属于“收藏排除”

```bash
gsettings get org.gnome.shell favorite-apps
```

若应用 ID 在列表里，则它不会出现在应用面板——这是 2.4 的设计行为。

## 四、修复方法

### 4.1 类型 A：重建多尺寸图标

适用：`Icon=` 是图标名，但主题查不到（多为只放了 1024 尺寸目录）。

```bash
# 通用工具：指定桌面项 + 图标母版，自动生成 6 档尺寸并刷新缓存
.venv/bin/python scripts/fix_desktop_launcher.py --desktop antigravity-ide.desktop \
    --icon-master install/assets/antigravity-ide.png

# Antigravity 系列应用也可以直接用安装脚本的图标模式
.venv/bin/python install/install_antigravity.py --app ide --icons-only
.venv/bin/python install/install_antigravity.py --app app --icons-only
```

手工等效操作（任意应用通用）：

```bash
python3 - <<'EOF'
from PIL import Image
from pathlib import Path
src = Path("/path/to/master.png")
base = Path("/usr/share/icons/hicolor")
for size in (512, 256, 128, 64, 48, 32):
    img = Image.open(src).convert("RGBA")
    img.thumbnail((size, size), Image.LANCZOS)
    canvas = Image.new("RGBA", (size, size), (0, 0, 0, 0))
    canvas.paste(img, ((size - img.width) // 2, (size - img.height) // 2))
    out = base / f"{size}x{size}/apps" / "icon-name.png"
    out.parent.mkdir(parents=True, exist_ok=True)
    canvas.save(out)
EOF
sudo gtk-update-icon-cache -f -t /usr/share/icons/hicolor
```

### 4.2 类型 B：补 StartupWMClass（用户级覆盖）

适用：应用运行后 Dock 上是灰色齿轮；`WM_CLASS` 与桌面项 ID 对不上。

```bash
# 自动探测运行窗口的 WM_CLASS（取面积最大的窗口，避开隐藏辅助窗口）
.venv/bin/python scripts/fix_desktop_launcher.py --desktop yunshu.desktop

# 应用没运行、或需要显式指定时
.venv/bin/python scripts/fix_desktop_launcher.py --desktop yunshu.desktop \
    --wm-class YunshuCross --name 云枢

# 只检查
.venv/bin/python scripts/fix_desktop_launcher.py --desktop yunshu.desktop --check
```

脚本行为：

1. 以现有桌面项为模板生成 `~/.local/share/applications/<id>.desktop`（不改系统文件，原覆盖项自动备份为 `.bak`）；
2. 补 `StartupWMClass`（写入 `[Desktop Entry]` 组内，不会误落到 `[Desktop Action ...]` 组）；
3. `Name=` 为空时用 `Name[zh_CN]` 兜底，并补齐只有本地化版本的 `GenericName`；
4. 剔除误填的 `Version=`；
5. 执行 `desktop-file-validate` + `update-desktop-database`。

> GNOME 会在桌面项变化后自动重新关联**已经运行**的窗口，通常无需重启应用；个别情况重启应用或重新登录即可。

### 4.3 类型 C：面板可见性

二选一（GNOME 不提供“Dock 固定 + 面板显示”的组合）：

```bash
# 只在面板显示：从收藏中移除（Dock 上也会消失）
python3 - <<'EOF'
import ast, subprocess
key = "org.gnome.shell favorite-apps"
current = ast.literal_eval(subprocess.check_output(["gsettings", "get", key], text=True))
drop = {"antigravity.desktop", "antigravity-ide.desktop"}
kept = [a for a in current if a not in drop]
subprocess.run(["gsettings", "set", key, "[" + ", ".join(f"'{a}'" for a in kept) + "]"], check=True)
print("已移除：", sorted(set(current) & drop))
EOF
```

本机现状：**保留 Dock 收藏**（图标已修复、可直接点击启动），因此应用面板内不列出属预期。

## 五、案例复盘

### 5.1 Antigravity IDE：重装后没有图标

| 项 | 内容 |
|---|---|
| 现象 | Dock 与桌面项显示灰色齿轮，应用面板里也找不到 |
| 证据 | `grep -c 1024x1024 index.theme` = **0**；图标只在 `hicolor/1024x1024/apps/`；`Gtk.IconTheme` 各尺寸全部 `❌` |
| 根因 | 类型 A（主题未索引 1024）+ 类型 C（在 `favorite-apps` 中被面板排除） |
| 修复 | 生成 6 档尺寸图标 + 刷新缓存；面板行为保持 GNOME 设计 |
| 验证 | `lookup_icon(64)` 返回 `.../64x64/apps/antigravity-ide.png`；Dock 显示彩色 Logo |
| 沉淀 | `install/install_antigravity.py --icons-only`、`install/assets/*.png` 母版 |

### 5.2 云枢：运行中但 Dock 无图标

| 项 | 内容 |
|---|---|
| 现象 | 云枢运行后，Dock 上是一个灰色齿轮，且没有应用名 |
| 证据 | `xprop` 显示 `WM_CLASS = "yunshucross","YunshuCross"`；桌面项 ID 为 `yunshu`，无 `StartupWMClass`；图标文件本身正常 |
| 根因 | 类型 B |
| 修复 | 用户级覆盖项补 `StartupWMClass=YunshuCross`，同时修 `Name=` 为空与非法 `Version=` |
| 验证 | 自检脚本窗口关联检查通过；Dock 显示蓝色云朵 Logo，无需重启云枢 |
| 沉淀 | `scripts/fix_desktop_launcher.py`（通用工具） |

### 5.3 顺带修正：Antigravity IDE 的 StartupWMClass

复核窗口发现 IDE 主窗口 `WM_CLASS` 是 `antigravity ide / Antigravity IDE`（带空格），原桌面项写的是 `antigravity-ide`，主窗口其实关联不上。已在 `install/install_antigravity.py` 的 `PROFILES["ide"]["wmclass"]` 更正为 `Antigravity IDE`，覆盖项与自检均通过。

## 七、检查清单

- [ ] `check_desktop_integration.py` 退出码 0（收藏全部 ✅、窗口全部可关联）
- [ ] `Gtk.IconTheme.lookup_icon(name, 64, 0)` 能返回实际 PNG 路径
- [ ] `/usr/share/icons/hicolor` 下存在 6 档尺寸文件，且 `gtk-update-icon-cache` 已执行
- [ ] 运行中窗口的 `WM_CLASS` class 段与桌面项 `StartupWMClass` 或 ID 一致
- [ ] `desktop-file-validate` 无 error（warning/hint 可接受）
- [ ] 用户级覆盖项存在时，其 `Icon`/`StartupWMClass` 位于 `[Desktop Entry]` 组内

## 八、注意事项

- **不要改厂商系统文件**：一律写 `~/.local/share/applications/` 覆盖项，应用升级后仍生效；覆盖项内容变化时会被复制为 `.bak`。
- **图标尺寸要落在已登记目录**：本机 hicolor 最大 512，1024 目录不参与索引；母版图保留 1024 即可，分发时缩放。
- **图标缓存必须刷新**：`gtk-update-icon-cache -f -t /usr/share/icons/hicolor`，否则 Dock 可能继续用旧缓存。
- **一个应用可能有多个 WM_CLASS**：优先取面积最大的主窗口；不要用 10x10 的辅助窗口。
- **GNOME 收藏与面板互斥**：需要面板可见就取消收藏，需要 Dock 固定就接受面板不列出。
- **PyGObject 只在系统 Python**：脚本检测到 `.venv` 缺 `gi` 会自动切到 `/usr/bin/python3`；图标生成需要在 `.venv` 内装 `Pillow`（`requirements.txt` 已登记）。
- **X11 限定**：`xprop`/`xwininfo` 取窗口信息依赖 X11；Wayland 会话需改用其他方式（本机为 X11）。
