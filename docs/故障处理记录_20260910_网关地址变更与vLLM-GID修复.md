## 1. 现象

- 客户端（本机 `desktop-mlq4p1s`）访问 LiteLLM 网关"连接错误"，`172.19.9.104` 完全不可达。
- `chat/completions` 若可达则报 500；vLLM 后端 `:18090` 无监听。
- 直连链路看似正常但集群起不来。

## 2. 根因（三个叠加问题）

### 2.1 网关地址变了（客户端配置失效）
工作站（LiteLLM 网关宿主）的**有线管理口 `enP7s7` 已断/未插**，原固定地址 `172.19.9.104` 失效；工作站现走**无线 `wlP9s9` = `172.19.50.70`（WN-Office）**。
客户端（`.env` / `opencode.json` / `.claude/settings.json`）仍指向 `172.19.9.104`，故"不通"。

### 2.2 Node1 的 RoCE GID index 漂移
双机直连 fabric（工作站 `192.168.100.10` ↔ Node1 `192.168.100.11`）本身正常，但：

| 节点 | HCA | `.env` 配置 | 实际 **RoCEv2 IPv4** index |
|---|---|---|---|
| Node1（rank1）| `rocep1s0f0` | `IB_GID_INDEX=3` | **4**（idx3 变空）❌ |
| 工作站（rank0）| `rocep1s0f1` | `IB_GID_INDEX=3` | **3** ✅ |

Node1 照旧配置启动会读到空 GID → NCCL/`ibv_modify_qp` 失败，双机起不来。

### 2.3 集群处于半死 + watchdog 缺陷
- Node1 rank1 容器 `Exited (137)`；工作站 rank0 容器被 watchdog 反复拉起但等不到 rank1。
- **watchdog Bug**：`~/ops/watchdog-vllm.sh` 用 `COMPOSE_DIR=/home/winbot/...` 去 SSH 重启 Node1，而 Node1 实际路径是 `/home/dgxdeploy/...` → 自愈重启 rank1 永远失败。

> 另：退役机 Node0（`cube-fe5e`，172.19.51.123）的 CX7 四口无缆属**正常**——按迁移方案 B3，光纤已移到工作站。其网卡热插拔消失已用 `mtk-hotplug-handler.sh plug-in` 恢复，但该机不再承担服务。

## 3. 修复操作

### 3.1 客户端地址（本机，均含备份）
| 文件 | 变更 |
|---|---|
| `~/.config/opencode/opencode.json` | `dgx.baseURL` → `http://172.19.50.70:4000/v1` |
| `~/.claude/settings.json` | `ANTHROPIC_BASE_URL` → `http://172.19.50.70:4000` |
| 仓库 `.env` | `LITELLM_HTTP/HTTPS_URL` → `172.19.50.70` |

### 3.2 Node1 GID（含备份）
```bash
cd ~/deepseek-v4-vllm/upstream
cp -a .env.canary128 .env.canary128.bak-gidfix-<ts>
cp -a .env.canary64  .env.canary64.bak-gidfix-<ts>
sed -i 's/^IB_GID_INDEX=3$/IB_GID_INDEX=4/' .env.canary128 .env.canary64
```

### 3.3 按序重启（文档顺序：rank1 先、rank0 后）
```bash
# 先设维护标记，暂停 watchdog
touch /home/winbot/.vllm_maintenance
# Node1（rank1）
cd ~/deepseek-v4-vllm/upstream && docker compose --env-file .env.canary128 down && docker compose --env-file .env.canary128 up -d
# 工作站（rank0）
cd ~/deepseek-v4-vllm/upstream && docker compose --env-file .env.canary128 down && docker compose --env-file .env.canary128 up -d
```

### 3.4 修正 watchdog（工作站）
- 新增 `N1_COMPOSE_DIR=/home/dgxdeploy/deepseek-v4-vllm/upstream`，SSH 重启 Node1 时改用它；
- 本地 `cd "$COMPOSE_DIR"`（`/home/winbot/...`）不变；
- 备份：`/home/winbot/ops/watchdog-vllm.sh.bak-<ts>`；`bash -n` 语法通过。

### 3.5 收尾
`rm /home/winbot/.vllm_maintenance`（恢复 watchdog 自愈）。

## 6. 静态地址（2026-09-10 追加，已实施）

```bash

  ipv4.method manual \
  ipv4.addresses 172.19.50.70/22 \
  ipv4.gateway 172.19.51.254 \
  ipv4.dns "172.16.0.14,172.17.1.14"
```

  （NM 变更自动写回 netplan；`netplan generate` rc=0）。

- 验证：`ip route` default via `172.19.51.254`（proto static）；ping 网关 OK；本机经 `172.19.50.70:4000` 推理 `STATIC_OK`。
