# 故障处理记录 — 工作站 RDP 无法访问(GNOME Remote Desktop 服务重启)

> 记录日期:2026-09-04
> 关联主机:工作站 `cube-fe5e` @ `172.19.51.123`(系统用户 `bot`)
> 远程桌面:GNOME 自带远程桌面(gnome-remote-desktop,RDP `:3389`)
> SSH/登录密码等敏感信息:见仓库根目录 `.env`(已 gitignore,禁止提交,本文件不重复明文)

## 1. 背景与现象

用户反馈工作站 `172.19.51.123` 的远程桌面「不能正常访问」,要求 SSH 登入并重启其远程桌面服务。

现象归纳:

- 主机系统层面正常:SSH 可达,`bot` 用户有活跃图形会话(gdm / seat0 / tty2,自 2026-08-26 登录);
- 远程桌面(RDP :3389)无法建立正常连接;
- 故障源定位为 **GNOME Remote Desktop 守护进程运行 1 周以上后进入异常状态**。

## 2. 诊断过程

### 2.1 入口:本机无 SSH 客户端

排障机(Windows)未安装可用的 `ssh`/`plink`,遂下载 **plink 0.85**(单文件,官方 PuTTY 站点)用于密码登录:

- 首次连接时 plink 提示「host key 与缓存不符」;用 `ssh-keygen -lf` 计算本机 `known_hosts` 中该 IP 的 ed25519 公钥指纹,与 plink 报告的服务器当前密钥指纹**完全一致**(`SHA256:IaegCHqRZ0OWMZmMfZAviG9DSOTCfsQO8/QXbxGW7aY`)→ 判定仅 plink 缓存为旧密钥(服务器密钥曾重建),非 MITM;
- 之后连接统一显式指定 `-hostkey "SHA256:Iaeg..."` + `-batch`,稳定无提示。

### 2.2 服务/进程排查

| 步骤 | 命令/动作 | 结论 |
|---|---|---|
| 1. 服务枚举 | `systemctl list-units \| grep -iE 'xrdp\|vnc\|lightdm\|gdm'` | gdm 运行中;**无 xrdp/vnc 服务在跑** |
| 2. 端口检查 | `ss -tlnp \| grep 3389` | `:3389` 由 **`gnome-remote-de`**(gnome-remote-desktop,pid 540704)监听 |
| 3. 进程归属 | `cat /proc/540704/cgroup`;`ps -fp 3339` | 运行在 **user systemd 单元** `user@1000.service/app.slice/gnome-remote-desktop.service`(systemd --user pid 3339),非系统级单元 |
| 4. 配置确认 | `gsettings get org.gnome.desktop.remote-desktop.rdp enable` | `true`(RDP 已启用) |
| 5. 服务日志 | `journalctl --user -u gnome-remote-desktop` | 旧守护进程(自 08-26 运行)近期反复报 **`rdp_server_accept_nego: Protocol security negotiation failure`**,连接无法完成协商 → 表现为「连不上」 |
| 6. 旁证:xrdp | `systemctl status xrdp` | 系统另装 xrdp 0.9.24(disabled/dead,非本次所用服务) |

> 关键结论:用户实际使用的是 **GNOME 自带远程桌面**,进程托管在 **bot 的 user systemd** 下,不能用 `systemctl restart`(系统级)操作,须在用户会话内执行 `systemctl --user`。

## 3. 修复操作

### 3.1 重启 GNOME 远程桌面服务(用户级单元)

```bash
export XDG_RUNTIME_DIR=/run/user/1000
systemctl --user restart gnome-remote-desktop
```

单元信息:`/usr/lib/systemd/user/gnome-remote-desktop.service`(enabled),含用户级 drop-in:
`/home/bot/.config/systemd/user/gnome-remote-desktop.service.d/10-restart.conf`、`20-env.conf`。

重启结果(关键证据):

- `Active: active (running) since 2026-09-04 14:09:37`;**Main PID 540704 → 1482078**(全新进程);
- 服务日志输出 **`RDP server started`**,无协商报错;
- 端口确认:`ss -tlnp` 显示 `*:3389` 由新进程 `gnome-remote-de(pid=1482078)` 监听。

### 3.2 附带还原:xrdp 冲突处置

排查中曾测试启动 xrdp(原本 disabled/dead),它尝试绑定 `:3389` 被 GNOME 服务占用而失败
(`g_tcp_bind(7, 3389) failed bind ... address already in use`)。由于实际使用的是 GNOME 服务,
已执行还原,避免 xrdp 开机自启抢端口:

```bash
sudo systemctl disable xrdp        # 还原为 disabled(移除 multi-user.target.wants 软链)
sudo systemctl reset-failed xrdp   # 清掉 failed 状态
```

## 6. 经验与后续建议

1. **分清服务归属再重启**:GNOME Remote Desktop 是**用户级 systemd 单元**(挂在登录用户的
   `systemd --user` 下),SSH 进来后需 `XDG_RUNTIME_DIR=/run/user/<uid>` 才能用 `systemctl --user`;
   用系统级 `systemctl restart` 会提示找不到该单元。
2. **xrdp 与 GNOME RDP 同抢 :3389**:两者不能共存,若日后要启用 xrdp,须先停用 GNOME 远程桌面
   (Settings → Sharing → Remote Desktop,或停对应 user 单元),反之亦然。
3. **长期运行的会话守护进程建议周期性重启**:本次旧进程运行 1 周多后 RDP 协商开始失败,
   重启即恢复;可考虑对 `gnome-remote-desktop.service` 加定时(如每周)重启或健康探活。
4. 排障机若缺 SSH 客户端,可用单文件 `plink -pw` + `-hostkey <指纹>` 免交互登录;首次连接务必核对
   host key(与 `known_hosts` 指纹比对),勿直接信任「cache 不符」提示。
