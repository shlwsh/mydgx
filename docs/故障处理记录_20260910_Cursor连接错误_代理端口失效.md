# 故障处理记录：Cursor 连接错误（代理端口失效）

> 日期：2026-09-10
> 主机：本机（Windows，工作站侧）
> 现象：通过代理服务（FlClash，7890）Codex 可正常联网，但 **Cursor 始终连接错误**
> 结论：Cursor 的 `http.proxy` 指向了一个已失效的本地代理端口 `127.0.0.1:54243`（由第三方插件 `cursor-free` 写入），导致所有网络请求被发往死端口。

---

## 1. 现象与证据

| 证据 | 内容 |
|---|---|
| Cursor `settings.json` | `"http.proxy": "http://127.0.0.1:54243"` |
| 端口监听 | `Get-NetTCPConnection -LocalPort 54243` → **无监听** |
| 实际代理 | FlClashCore 监听 **7890**（`vortex.json` 里的 7897 为旧值） |
| Cursor 网络日志 | `network.log`：`marketplace.cursorapi.com ... error POST Failed to fetch` |
| 插件自检 | `state.vscdb` 键 `jg.cursor-free`：`Version check failed: Failed to establish a socket connection to proxies: PROXY 127.0.0.1:54243` |
| 连通性验证 | Cursor 三域名经 7890 均 200（`marketplace.cursorapi.com` / `api2.cursor.sh` / `cursor.com`）；LiteLLM 网关直连与经 7890 均 200 |

## 2. 根因

- 第三方插件 **`jg.cursor-free` v2.9.4**（Cursor 令牌中转/破解插件）在启用代理时，把自己的**临时本地代理端口 54243** 写入了 Cursor 的 `http.proxy`。
- 该插件代理未在运行（端口无人监听），而 Cursor 仍把全部 HTTP(S) 请求发往 `127.0.0.1:54243` → **连接错误 / Failed to fetch**。
- 另有 `http.proxyKerberosServicePrincipal` 被误填为代理 URL（该字段应为 Kerberos SPN，属错误配置）。

## 3. 修正内容

文件：`C:\Users\Administrator\AppData\Roaming\Cursor\User\settings.json`
（备份：`settings.json.bak-20260910-090604`）

```jsonc
{
  // 由失效的 54243 改为实际代理端口 7890
  "http.proxy": "http://127.0.0.1:7890",
  // 本机/内网地址绕过代理（含 LiteLLM 网关 172.19.9.104）
  "http.noProxy": [
    "127.0.0.1",
    "localhost",
    "172.19.9.104",
    "172.19.0.0/16",
    "192.168.100.0/24"
  ],
  "http.proxySupport": "on"
  // 已删除错误的 "http.proxyKerberosServicePrincipal"
}
```

## 4. 生效方式

`http.proxy` 在网络层初始化时读取，建议**完全退出并重启 Cursor**（或 `Ctrl+Shift+P → Reload Window`）后验证。

## 5. 验证

- Cursor 扩展市场、Cursor 登录/同步等请求恢复正常（不再 `Failed to fetch`）。
- 如需验证代理本身：`curl.exe -x http://127.0.0.1:7890 -I https://marketplace.cursorapi.com/` → 200。

## 6. 注意事项 / 建议

1. **插件冲突**：`jg.cursor-free` 可能在启用时**再次覆写** `http.proxy`。若问题复现，请停用/卸载该插件，或在插件面板重新执行其 `启用代理`（其代理需在运行时才有正确端口）。
2. **端口漂移**：若 FlClash 修改了混合端口，需同步更新 `http.proxy`。建议在 FlClash 中固定端口为 7890。
3. **让 Cursor 用本地 DeepSeek（可选）**：在 Cursor Settings → Models 中：
   - 勾选 OpenAI API Key，填 `sk-dgx-local-2026`（或测试 key `dgx-validation-test`）；
   - Override OpenAI Base URL 填 LiteLLM 网关地址。
   - 若用 HTTPS `https://172.19.9.104:4443/v1`，需将网关自签证书导入 Windows「受信任的根证书颁发机构」，且证书需含 IP SAN（当前证书**无 SAN**，需重签）。
   - HTTP `http://172.19.9.104:4000/v1` 最省事，但 Cursor 对非 localhost 的 http 可能有限制，需实测。
