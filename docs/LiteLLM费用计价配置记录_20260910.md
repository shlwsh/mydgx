> 目标：为 LiteLLM 网关启用 **按 key 的费用计量**（此前仅记账、单价为 0、金额恒 0）

---

## 1. 背景与结论

已在 2026-09-10 启用 Postgres 虚拟 key + 用量日志（`LiteLLM_SpendLogs`），但各模型 `input_cost_per_token` / `output_cost_per_token` 均为 **0**，因此费用金额恒为 0，无法真正"计费/算钱"。

本次为 4 个模型配置 **DeepSeek-V4-Flash 官方价**（off-peak）：**输入 $0.22/1M、输出 $0.66/1M**，并给测试专用 key 设 **$2.0/30 天** 预算上限。经实测，token 成本已能正确计算并写入用量日志与 key 的 spend。

## 2. 计价标准（DeepSeek-V4-Flash，模型 deepseek-v4-flash-0731）

| 项 | 值 |
|---|---|
| input_cost_per_token | `2.2e-7`（= $0.22 / 1M tokens） |
| output_cost_per_token | `6.6e-7`（= $0.66 / 1M tokens） |
| 来源 | DeepSeek 官方 off-peak（cache miss）标准价 |

> 说明：采用 off-peak 标准价。未额外配置缓存命中价、peak 分时价；如需与官方完全一致，可后续在 `model_info` 里补 `cache_read_input_token_cost` 与分时定价。

## 3. 变更内容

  input_cost_per_token: 2.2e-7

## 4. 验证结果（实测通过）

| 检查项 | 结果 |
|---|---|
| `/model/info` 各模型 cost | 全部 `in=2.2E-07` / `out=6.6E-07` |
| 测试 key 推理 | `COST_OK`，13 in + 4 out = 17 tokens |
| SpendLogs 成本 | 17 tokens → `spend=5.5E-06`（=13×2.2e-7 + 4×6.6e-7），**计算吻合** |
| 历史大请求追溯 | 81102 tokens → $0.000633；80327 → $0.000413 |
| 测试 key spend / budget | `spend=5.5E-06` ≤ `max_budget=2.0` |

## 5. 查询用量与金额

```bash
# 某 key 累计花费（spend 单位为美元）
curl 'http://172.19.50.70:4000/key/info?key=<key>' -H 'Authorization: Bearer sk-dgx-local-2026'

# 全部调用记录（含每天 cost/spend）
curl 'http://172.19.50.70:4000/spend/logs' -H 'Authorization: Bearer sk-dgx-local-2026'

# 直接查 PostgreSQL（可按 key/时间/token/金额分析）
PGPASSWORD=litellm_pg_2026 psql -h 127.0.0.1 -U litellm_user -d litellm \
  -c "SELECT \"startTime\", model_group, total_tokens, usage_cost AS cost_usd, api_key
      FROM \"LiteLLM_SpendLogs\" ORDER BY \"startTime\" DESC LIMIT 20;"
```
