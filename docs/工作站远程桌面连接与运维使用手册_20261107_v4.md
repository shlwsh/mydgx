## 1. 架构说明与历史故障根因

前期测试曾采用 Ubuntu 24.04 的实验性系统级 `gnome-remote-desktop`（Remote Login），在无物理屏幕（headless）与 NVIDIA GPU 环境下暴露了严重缺陷：

1. **Node0 登录后卡死**：GDM 默认启用 Wayland，无物理显示器时虚拟合成器崩溃；系统级 RDP 发起的 `Server Redirection` 握手被 Windows 客户端拒绝，导致登录界面挂起。
2. **Node1 无法连接**：Node1 曾因 WiFi 自动跳连访客网络 `WN-Visitor`，IP 漂移至 `172.19.21.160`，造成网络隔离不可达。

### 现行稳定架构（已全量上线并通过双机重启验证）

- **底层引擎**：工业级成熟稳定的 **`xrdp` + `xorgxrdp`** 架构，监听标准 `3389/tcp`；
- **独立 X11 图形会话**：通过 `/etc/xrdp/startwm.sh` 与 `~/.xsessionrc` 预加载 `ubuntu:GNOME` 完整桌面环境，绕过脆弱的 Wayland 重定向机制；
- **Tailscale 首选通道（三节点统一）**：三节点均已登录同一 tailnet (`shlwsh@`)，通过 `100.x` 地址互访
  - 该通道**不依赖 WiFi 状态与地址分配**，彻底规避 IP 漂移导致的失联；
  - 基于 WireGuard 端到端加密，仅需节点加入 tailnet 即可，无需额外网络配置；
  - 本机 / Node0 / Node1 三方同网段，`tailscale status` 互见在线。
- **管理网兜底（三节点统一热点）**：三节点接入企业热点 **`WN-Office`**（802.1X PEAP），同处 `172.19.48.0/22` 管理网
  - Node1 管理地址 `172.19.49.159/22`，网关 `172.19.51.254`；
  - Node1 上 `WN-Visitor` 等其余热点 `autoconnect` 已全部关闭，杜绝重启后回落漂移。
- **高速互联口兜底**：Node0 `192.168.100.10` ↔ Node1 `192.168.100.11` 为物理直连（`/24`），不依赖 WiFi；
  该网段**仅在两节点之间直连**，普通管理机无此网卡，需借道 Node0 跳板才能触达（详见 §4.4）。
- **开机自启**：`xrdp`、`xrdp-sesman`、`tailscaled` 与 `ssh` 服务随系统自启，LLM 模型默认不自启，可用内存保持 114～118GiB。

### 1.2 Node1 无线掉线根因与加固（2026-11-07）

**现象**：Node1 于 06:55 丢失管理网地址，ping 100% 丢包，RDP 不可达。

**根因链**（`journalctl -u NetworkManager` 实证）：

```text
06:54:13  device (Meta): state change: activated -> unmanaged
06:55:18  keyfile: deleting netplan connection: NM-dc21e7ea-624b-42b3-95e9-71902ab232dd
06:55:18  audit: op="connection-delete" name="yunshu_WN-Office"
```

FlClash 退出 TUN 模式时撤掉 `Meta` 虚拟网卡 → NetworkManager 检测到路由变化 → 重写 netplan → 把 `yunshu_WN-Office` 当成陈旧数据删除 → 无线断开。

**加固措施（三层）**：

| 层 | 措施 | 位置 |
|---|---|---|
| 清除根源 | 卸载 FlClash 全部残留（悬空软链、`/usr/share/FlClash/`、数据目录、桌面项、`tun0` 网卡） | Node1 |
| 隔离 | NM 忽略虚拟网卡，避免其状态变化触发 netplan 重写 | `/etc/NetworkManager/conf.d/99-ignore-virtual-nics.conf` |
| 兜底 | 每 5 分钟检查配置与连接，缺失即自动重建并 `netplan apply` | `wifi-guard.service` / `.timer`，日志 `/var/log/wifi-guard.log` |

`99-ignore-virtual-nics.conf` 内容要点：

```ini
[keyfile]
unmanaged-devices=interface-name:Meta;interface-name:tun*;interface-name:wg*;interface-name:clash*;interface-name:docker*;interface-name:br-*
```

> **关联收益**：Tailscale 通道本身不依赖 WLAN，因此即便管理网再次异常，远程桌面仍可通过 `100.103.250.108` 接入。

### 1.3 Node1 Clash Verge Rev 修复（2026-11-07）

**故障一：节点选择不稳定**

`自动选择`（`url-test`）组固定选用 `🇰🇷Korea 02`，该节点间歇性超时：

```text
error: kr2.oh-node.com:443 connect error: context deadline exceeded
```

实测延迟（API 内置历史）：🇺🇸 United States 03 = **170ms**（最优），🇰🇷 Korea 02 = **1398ms**（超时源）。

调优参数（写入**持久化**配置 `clash-verge.yaml`，`runtime/config.yaml` 会被重载覆盖）：

| 参数 | 原值 | 新值 | 原因 |
|---|---|---|---|
| `interval` | `300` | `120` | 检测太迟钝 |
| `timeout` | `2000` | `5000` | 2s 内判不出失败，误判超时节点可用 |
| `tolerance` | `50` | `20` | 容差过大，不肯切换 |
| `lazy` | `true` | `false` | 惰性检测，无流量时完全不探活 |

**故障二：服务重启后核心无法自启**

```text
Failed to restore desired core state on startup; core will not be auto-started.
failed to open core IPC directory "/run/clash-verge-service/users/1000": No such file or directory
```

`/run` 为 tmpfs，systemd 仅重建 `RuntimeDirectory=clash-verge-service`，但 Clash Verge Rev 需要的嵌套 `users/1000` **不会自行创建**（软件固有缺陷）。

**修复**：新增 drop-in `/etc/systemd/system/clash-verge-service.service.d/10-prepare-runtime.conf`

>
> `/cert:ignore` 用于跳过自签名证书校验，**仅适用于内网可信环境**。

### 4.4 高速互联口兜底与跳板隧道（管理网失联时）

Node0 与 Node1 之间除 WiFi 外还有一条 **RJ45 物理直连**通道：

| 节点 | 高速口地址 | 网卡 | 对端 |
|---|---|---|---|
| Node0 | `192.168.100.10/24` | `enp1s0f1np1` | Node1 |
| Node1 | `192.168.100.11/24` | `enp1s0f0np0` | Node0 |

该网段**仅在两节点之间直连**，本机（`cube-fe5e`）并无此网卡，因此触达方式如下：

- **SSH 巡检 / 会话重置**：`rdp_session_reset.py` 直连失败后自动经 Node0 建立 `direct-tcpip` 隧道，
  日志会输出「已通过 Node0 跳板建立到 `<ip>` 的隧道」；
- **RDP 连接**：`rdp_connect.py` 在本机 `127.0.0.1:3390` 起监听，经 Node0 转发至远端 `3389`，
  随后客户端连接本地端口即可看到真实桌面。

```bash

NODE1_MGMT_IP=172.19.99.199 .venv/bin/python scripts/rdp_session_reset.py --node node1 --check
# 预期输出：回退到高速互联口 192.168.100.11 → 已通过 Node0 跳板建立隧道 → 巡检正常

# 验证 RDP 转发
.venv/bin/python scripts/rdp_connect.py --node node1 --check
```

> **通道优先级提示**：v4.0 起默认先试 Tailscale，因此要复现「管理网不可达 → 高速口兜底」，
> 需同时屏蔽 Tailscale 通道（如 `--via mgmt` 配合伪造管理 IP）。
> 若 Node0 自身也失联，则高速口通道同样不可用，此时只能到机房本地处理。

### 4.6 Tailscale 直连优化与 UDP 端口规划

**背景**：三节点位于同一办公网出口，公网 IP 均为 `59.49.101.30`，且 `tailscaled` 默认都用 UDP `41641`。
办公网 NAT 在同一时刻只能为 `41641` 保留一个映射，因此：
- 只有一台节点能拿到 `59.49.101.30:41641` 的直连，且归属会在节点重启/重绑后漂移；
- 其余节点被迫走 DERP 中继（默认可能选到 `sfo` / `nue`，实测 400ms～1.5s）。

**端口规划（三节点共用公网 IP，必须互不冲突）**：

| 节点 | Tailscale IP | UDP 端口 | 直连实测（TCP:22 / `tailscale ping`） |
|---|---|---|---|
| Node0 `cube-f22b` | `100.67.107.19` | `41641`（默认，保留不动） | `59.49.101.30:41641`，≈ **15ms** |
| Node1 `cube-0137` | `100.103.250.108` | `41642` | `59.49.101.30:41642`，≈ **12～13ms** |
| Node123 `cube-fe5e` | `100.79.120.65` | `41643` | `59.49.101.30:41643`，≈ **16ms** |

> 办公网 NAT 为 **endpoint-independent（`MappingVariesByDestIP: false`）且端口保持（port-preserving）**，
> 因此节点内网端口会原样映射为公网端口；把三台端口错开即可让三台同时保持直连。

**持久化配置（在各节点执行，以 Node1 为例）**：

```bash
# 修改 Debian/Ubuntu 包的端口变量（重启后仍生效）
sudo sed -i.bak 's/^PORT=.*/PORT="41642"/' /etc/default/tailscaled
grep '^PORT=' /etc/default/tailscaled     # 确认 PORT="41642"
sudo systemctl restart tailscaled

# 端口生效校验
sudo ss -lunp | grep -i tailscaled        # 应看到新端口
tailscale netcheck | grep -E 'IPv4|MappingVariesByDestIP|PortMapping'
```

各节点端口对应：Node0=`41641`、Node1=`41642`、Node123=`41643`。
新增节点接入时，**务必从 `41644` 起继续分配**，禁止与现用端口重复。

**客户端侧验证**：

```bash
tailscale status | grep cube-            # 期望三行均显示 direct 59.49.101.30:41xxx
tailscale ping cube-f22b                 # 首包可能走 DERP，随后应转为直连
tailscale ping cube-0137
tailscale ping cube-fe5e
```

> 说明：若某节点短暂显示 `relay "sfo"`，可在客户端执行 `tailscale debug rebind` + `tailscale debug restun`
> 触发一次重新穿透；仍无法直连时，检查该节点 UDP 端口是否与其它节点冲突。
> 本机 macOS 客户端同样适用该端口规划（本地开源 `tailscaled` 已按 utun 模式运行）。

## 5. 关键运维配置与注意事项

1. **色彩管理弹窗已免疫（三节点）**：均已配置 `/etc/polkit-1/localauthority/50-local.d/45-allow-colord.pkla`，远程登入后不会弹出「Authentication Required to create a color managed device」授权窗。
2. **Wayland 已禁用（三节点）**：`/etc/gdm3/custom.conf` 中固化 `WaylandEnable=false`，杜绝 Wayland 驱动不兼容导致的无响应。
3. **GDM 自动登录已关闭（三节点）**：本地不再常驻同用户的图形会话，避免与远程 xrdp 会话争抢用户 D-Bus 总线上的 `org.gnome.Shell` / `org.gnome.Mutter.ServiceChannel`（该争抢是 Node123 切换 GNOME 时的关键坑位，详见 §1.1.1）。
4. **连接默认用户**：Node1 的 RDP 默认用户为 **`his_test`**，不再用 `dgxdeploy` 接入（`dgxdeploy` 仅保留给 SSH 运维）；Node0 默认 `winbot`，Node123 默认 `bot`。
5. **SSH 口令与 RDP 口令不同**：Node123 的 SSH 运维口令与 RDP 登录口令是两套凭据，均记录在 `.env`（`SSH_NODE123_PASS` / `NODE123_RDP_PASS`），不可混用。
6. **断开与会话保持**：直接关闭远程桌面窗口，后台会话不会被杀掉；下次重新连入将直接回到未关闭的窗口与终端（实测会话显示号为 `:10`）。
   > ⚠️ 但若客户端被 `SIGTERM` 强杀或网络异常中断，可能留下僵死会话导致黑屏，此时用 `bun run rdp:reset` 清理。
7. **内存保持充裕**：DeepSeek LLM 服务默认开机不自启，两台工作站内存占用仅 3.5～5.0GiB，可用内存超 110GiB。Node123 内存占用更高，主因容器网桥与容器负载（k3s / mysqld），与 RDP 无关。
8. **客户端兼容性**：Linux 下建议使用 FreeRDP 3.x（`xfreerdp3`），Ubuntu 22.04 及更早系统仅有 `xfreerdp` 2.x，参数基本兼容。
   **必须加 `/rfx` + `/bpp:24`**，详见 §3.3。
9. **自签名证书**：服务端使用 `/etc/xrdp/cert.pem` 自签名证书，客户端必须 `/cert:ignore` 或手动信任该证书。
10. **端口前置代理**：本机若配置了 HTTP 代理（如 `http://127.0.0.1:7897`），FreeRDP 会自动读取 `http_proxy` 环境变量，请确保 `172.19.0.0/16` 与 `100.64.0.0/10` 在 `no_proxy` 白名单内，否则连接会被代理劫持。
11. **多显示器**：建议统一使用 `/dynamic-resolution` 让远程桌面跟随本地窗口尺寸自适应；
    但**老旧 xrdp 服务端除外**（会导致握手失败，见 §3.3）。
12. **不要用 `timeout` 强杀客户端**：`timeout 20 xfreerdp3 ...` 会留下远端僵死会话。如需限时测试，请改用 `--check`（仅巡检）或在测试后执行 `bun run rdp:reset`。
13. **本机桌面为 Wayland**：所有 GUI 客户端在 Wayland 下对 X11 自动化工具不可见，脚本已统一处理。
14. **GNOME 会话切换与验证**：三节点统一为 GNOME Desktop 后，若需调整会话入口，用 `scripts/deploy_gnome_session.py`（支持 `--apply` / `--rollback`），验证用 `scripts/verify_xrdp_real_login.py`（完整复刻 sesman 会话创建链路，无需 RDP 客户端）。
15. **三节点统一 `WN-Office` 热点**：802.1X PEAP 认证，Node1 上其余热点 `autoconnect` 已全部关闭。
    若日后需恢复平铺等窗口管理功能，请勿重新启用系统自带的 `tiling-assistant`（会导致 GNOME Shell 崩溃）。
16. **端口检测不可用裸 TCP**：本机存在 Clash TUN 虚拟网卡，被代理接管的连接会「假性」建立成功，
    导致不存在的地址也被判定为可达。脚本已改用 RDP 协议握手校验（`probe_rdp_service`），
    自定义巡检脚本时务必注意这一点。
17. **`tailscaled` 不要指向本地代理**：Node1 曾因 `tailscaled` 配置了 `127.0.0.1:7890` 而该端口无代理运行，
    导致 Tailscale 掉线。如需代理，请填真实可用地址。
18. **Node123 的 SSH 巡检失败为既有现象**：本机 SSH 禁用密码登录，`rdp_connect.py` 对 Node123 的
    远端 SSH 巡检会返回 `Authentication failed`。该现象在管理网通道下同样存在，与 Tailscale 改造无关，
    **不影响 RDP 实际连通性**（RDP 探测与真实连接均正常）。
19. **【v4.0】Tailscale 三节点互访已验证**：`tailscale status` 显示三节点同处 tailnet `shlwsh@` 且互相在线；
    `xrdp` 监听 `*:3389`（全接口），因此 `100.x` 地址可直接承接 RDP。
20. **【v4.0】新增节点接入 Tailscale 的标准流程**：
    ```bash
    # 1) 安装（ARM64 示例，源需与系统代号匹配：noble）
    curl -fsSL https://pkgs.tailscale.com/stable/ubuntu/noble.tgz | tar -xz -C /tmp
    sudo cp /tmp/tailscale_*.deb /tmp/ 2>/dev/null
    sudo apt install -y /tmp/tailscale_*.deb
    # 或配置官方源后 apt install tailscale
    sudo systemctl enable --now tailscaled
    # 2) 登录（生成一次性链接，浏览器完成授权）
    sudo tailscale up --hostname=<主机名>
    # 3) 确认地址并写入 .env
    tailscale ip -4
    ```
21. **【v4.0】`--via` 通道强制选项**：`--via ts` 仅试 Tailscale、`--via mgmt` 仅试管理网、
    `--via auto`（默认）按 Tailscale → 管理网 → 高速口顺序回退。排障时可用其快速定位是哪条通道异常。

## 6. 故障速查表

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 连接超时无响应 | 网络不通 / 防火墙拦截 | `bun run rdp:check` 查看地址来源；确认 Node1 未漂移到访客网络 |
| **Tailscale 通道连不上** | **节点未登录 tailnet / `tailscaled` 未自启 / 指向失效代理** | **`tailscale status`；`systemctl is-active tailscaled`；检查 `override.conf` 的 `HTTP_PROXY`** |
| **Tailscale 显示 offline** | `tailscaled` 指向了本地代理但该代理未运行 | `journalctl -u tailscaled \| grep -i proxy`；清空 drop-in 中的代理配置 |
| **Tailscale 访问很慢 / 走 DERP 中继** | **多节点共用公网 IP 且 UDP 端口同为 `41641`，NAT 只能保留一个映射，直连归属漂移** | **按 §4.6 给各节点分配不同 UDP 端口（`41641/41642/41643`）并 `systemctl restart tailscaled`；`tailscale status` 应显示 `direct`** |
| **Node1 无线突然掉线** | **FlClash TUN 网卡触发 NM 重写 netplan 删除无线连接** | **查看 `/var/log/wifi-guard.log`；`nmcli con up "yunshu_WN-Office"`；确认 `99-ignore-virtual-nics.conf` 生效** |
| **Clash 代理不通** | **url-test 固定选中超时节点 / 服务重启后核心未自启** | **调 `tolerance`/`interval` 参数；确认 `10-prepare-runtime.conf` 存在；`curl -x http://127.0.0.1:7890 https://www.gstatic.com/generate_204`** |
| **登录成功但黑屏** | **残留僵死会话被复用（`reconnected session`）** | **执行 `bun run rdp:reset` 清理会话后重连** |
| 登录窗后黑屏 | `gnome-shell` 未启动 / Wayland 冲突 | 检查 `~/.xsessionrc` 是否预加载 `ubuntu:GNOME`；确认 `WaylandEnable=false` |
| **登录窗后黑屏（GNOME 会话）** | **`gnome-session` 未指定会话名**：无参 `gnome-session-binary` 不会选中 `ubuntu.session` | **确认 `~/.xsession` 内为 `exec gnome-session --session=ubuntu`；或跑 `scripts/verify_xrdp_real_login.py` 验证** |
| **登录窗后黑屏（GNOME 会话）** | **本地 GDM 自动登录会话争抢 D-Bus 总线名**（`org.gnome.Shell` / `org.gnome.Mutter.ServiceChannel`） | **关闭 `AutomaticLoginEnable=false` 并重启 gdm；`loginctl list-sessions` 确认无同用户本地图形会话** |
| **登录窗后黑屏（GNOME 会话）** | systemd 用户环境注入 `XDG_SESSION_TYPE=tty` | 入口脚本须显式 `export XDG_SESSION_TYPE=x11` 并 `unset WAYLAND_DISPLAY` |
| **登录成功后约 10 秒断开** | **服务端 xrdp 0.9.x 与 FreeRDP 3.x 图形编码协商不兼容** | **客户端追加 `/rfx` + `/bpp:24`，移除 `/dynamic-resolution`** |
| 登录后立刻断开 | 会话脚本报错 | `tail -n 50 /var/log/xrdp-sesman.log` 与 `~/.xsession-errors` |
| 认证失败 | 口令未同步 | `sudo chpasswd` 重置对应用户口令；检查 `/etc/polkit-1/` 与 PAM 规则 |
| 客户端报证书错误 | 服务端自签名证书 | 客户端追加 `/cert:ignore` |
| Remmina 无法连 RDP | 未安装 RDP 协议插件 | `sudo apt install -y remmina-plugin-rdp` |
| Remmina 窗口「抓不到」 | Wayland 会话下 X11 工具不可见 | 脚本已强制 `GDK_BACKEND=x11`；手工启动时同样追加该环境变量 |
| 画面卡顿 / 高延迟 | 未启用动态分辨率或编码 | 追加 `/dynamic-resolution`，降低 `/size` 分辨率 |
| 剪贴板不可用 | 通道未启用 | 客户端追加 `/clipboard` |
| `bun run` 报解释器错误 | 缺少 `.venv` 或 Node.js | 执行 `bun run setup` 建环境；确认 `node -v` 可用 |
| 端口 3389 不通 | 服务未自启 / IP 漂移 | `systemctl is-active xrdp`；检查 Node1 静态 IP 配置 |
| **节点整体失联（ping 不通）** | **WLAN 漂移到访客网络 / 热点认证失败** | `nmcli dev status \| grep wlP9s9`；确认已连接 `WN-Office` 且拿到 `172.19.48.0/22` 段地址 |
| 节点连上但地址是 `172.19.21.x` | 回落到 `WN-Visitor` 访客网络（与管理网隔离） | `sudo nmcli con up "yunshu_WN-Office"`；并关闭访客网络 `autoconnect` |
| 本机桌面崩溃（signal 6） | `tiling-assistant` 扩展与 mutter 断言冲突 | 已禁用该扩展；如需平铺请装上游新版 Tiling Assistant |
| 端口检测显示「开放」但实际不通 | Clash TUN 代理接管导致 TCP 假阳性 | 用 RDP 协议握手校验；勿用裸 `nc -z` 判断 |
| 高速口地址在本机不通 | `192.168.100.0/24` 仅节点间直连，本机无该网卡 | 走跳板：`bun run rdp:check` 会自动经 Node0 隧道 |

### 6.1 快速诊断决策树

```text
连接失败
├─ 服务探测 FAIL ─────────→ 换通道再试
│   ├─ --via ts 也不通 ────→ Tailscale 异常（tailscale status / tailscaled 自启 / 代理配置）
│   ├─ --via mgmt 不通 ───→ 管理网失联（热点漂移 / 认证失败）
│   ├─ 看地址来源标注 ────→ [高速互联口(需跳板)] 说明已自动走 Node0 隧道
│   └─ 仍是 [管理网(不可达)] → 检查热点连接与 Node0 是否在线
└─ 服务探测 PASS
   ├─ 认证失败 ───────────→ 核对 .env 中 NODE*_RDP_PASS / 远端 chpasswd
   ├─ 登录成功但黑屏 ─────→ bun run rdp:reset 后重连（僵死会话）
   ├─ 约 10 秒后断开 ─────→ 客户端加 /rfx + /bpp:24，去掉 /dynamic-resolution
   ├─ 登录窗后黑屏 ───────→ 检查 ~/.xsessionrc 与 WaylandEnable=false
   │                        └─ GNOME 会话专项：scripts/verify_xrdp_real_login.py
   │                           ├─ gnome-session 缺 --session=ubuntu → 修 ~/.xsession
   │                           ├─ 本地自动登录抢总线名 → AutomaticLoginEnable=false + 重启 gdm
   │                           └─ XDG_SESSION_TYPE=tty → 入口显式 export x11
   └─ 画面正常 ────────────→ ✅ 完成
```
