## 1. 架构说明与历史故障根因

前期测试曾采用 Ubuntu 24.04 的实验性系统级 `gnome-remote-desktop`（Remote Login），在无物理屏幕（headless）与 NVIDIA GPU 环境下暴露了严重缺陷：

1. **Node0 登录后卡死**：GDM 默认启用 Wayland，无物理显示器时虚拟合成器崩溃；系统级 RDP 发起的 `Server Redirection` 握手被 Windows 客户端拒绝，导致登录界面挂起。
2. **Node1 无法连接**：Node1 曾因 WiFi 自动跳连访客网络 `WN-Visitor`，IP 漂移至 `172.19.21.160`，造成网络隔离不可达。

### 现行稳定架构（已全量上线并通过双机重启验证）

- **底层引擎**：工业级成熟稳定的 **`xrdp` + `xorgxrdp`** 架构，监听标准 `3389/tcp`；
- **独立 X11 图形会话**：通过 `/etc/xrdp/startwm.sh` 与 `~/.xsessionrc` 预加载 `ubuntu:GNOME` 完整桌面环境，绕过脆弱的 Wayland 重定向机制；
- **网络固化（三节点统一热点）**：本机 / Node0 / Node1 全部接入企业热点 **`WN-Office`**（802.1X PEAP），同处 `172.19.48.0/22` 管理网；
  - Node1 管理地址 `172.19.49.159/22`，网关 `172.19.51.254`；
  - Node1 上 `WN-Visitor` 等其余热点 `autoconnect` 已全部关闭，杜绝重启后回落漂移；
- **高速互联口兜底**：Node0 `192.168.100.10` ↔ Node1 `192.168.100.11` 为物理直连（`/24`），不依赖 WiFi；
  该网段**仅在两节点之间直连**，普通管理机无此网卡，需借道 Node0 跳板才能触达（详见 §4.5）；
- **开机自启**：`xrdp`、`xrdp-sesman` 与 `ssh` 服务随系统自启，LLM 模型默认不自启，可用内存保持 114～118GiB。

```text
                    │  172.19.48.0/22   网关 172.19.51.254                    │

        本机 cube-fe5e          Node0 cube-f22b           Node1 cube-0137   │
```

#### 1.1.1 XFCE4 → GNOME 切换要点（2026-11-07 实施）

**根因**：家目录下的可执行 `~/.xsession`（`exec dbus-run-session -- startxfce4`）被 `/etc/X11/Xsession` 的
`50x11-common_determine-startup` 优先选中，从而把远程会话锁定在 XFCE4。

**切换步骤**（已由 `scripts/deploy_gnome_session.py --apply --restart-gdm` 自动化）：

| # | 操作 | 目的 |
|---|---|---|
| 1 | 备份 XFCE 版 `~/.xsession` → `~/.xsession.xfce.bak.*` | 保留回滚能力 |
| 2 | 写入 `~/.xsessionrc` | 对齐 Node0：导出 `ubuntu:GNOME` / `XDG_SESSION_TYPE=x11` / `GDK_BACKEND=x11` |
| 3 | 安装 GNOME 会话入口 `~/.xsession` | **必须显式 `exec gnome-session --session=ubuntu`**（见下方坑位一） |
| 4 | 部署 `45-allow-colord.pkla` | 抑制色彩管理授权弹窗 |
| 5 | 对齐 `sesman.ini` 的 `[Xorg]` 参数 | 移除 Node0 不存在的 `-keeptty` / `-novtswitch` |
| 6 | `WaylandEnable=false` + `AutomaticLoginEnable=false`，重启 gdm | 见下方坑位二 |
| 7 | 清理 XFCE 残留并重启 `xrdp-sesman` | 使下次连接重建 GNOME 会话 |

**坑位一：必须显式指定会话名**

`/usr/bin/x-session-manager` 最终执行的是 `exec /usr/libexec/gnome-session-binary "$@"`，**参数为空**。
无参数的 `gnome-session-binary` 不会选中 `/usr/share/gnome-session/sessions/ubuntu.session`，
因此 gnome-shell 不会启动（现象：登录后黑屏，且日志无任何报错）。

> 验证结论：`gnome-session --session=ubuntu` → gnome-shell 正常启动；
> `gnome-session-binary`（无参） → gnome-shell 不启动。

**坑位二：本地自动登录会与远程会话争抢 D-Bus 总线名**

本机原先开启 `AutomaticLoginEnable=true`，本地常驻一个同用户的 GNOME 会话，与远程 xrdp 会话
争抢同一用户 D-Bus 总线上的 `org.gnome.Shell` / `org.gnome.Mutter.ServiceChannel`，
后启动者获取不到总线名即静默退出（`Lost or failed to acquire name org.gnome.Mutter.ServiceChannel`）。

> Node0 / Node1 均未启用自动登录，故无此问题；本机已按基线关闭 `AutomaticLoginEnable`。

**坑位三：systemd 用户环境注入 `XDG_SESSION_TYPE=tty`**

开启自动登录期间，systemd 用户环境会向 xrdp 会话注入 `XDG_SESSION_TYPE=tty`，
gnome-shell 检测到非图形会话类型即拒绝启动。入口脚本已显式 `export XDG_SESSION_TYPE=x11`
并 `unset WAYLAND_DISPLAY`。

项目提供统一连接脚本 [`scripts/rdp_connect.py`](file:///home/bot/work/mydgx/scripts/rdp_connect.py)，自动探测本机可用客户端并完成连接。

```bash
# 0) 首次准备虚拟环境（等价于 bun run setup）
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

.venv/bin/python scripts/rdp_connect.py --node all

.venv/bin/python scripts/rdp_connect.py --node node0 --size 1920x1080
```

### 4.2 会话重置（解决登录后黑屏）

xrdp 会话在客户端异常断开后，服务端可能残留「僵死」GNOME 会话；此时重连会命中
`reconnected session`（复用旧显示号），表现为**登录成功但黑屏**。用会话重置工具清理：

```bash
# 仅巡检会话状态
bun run rdp:reset-check

# 强制重置全部节点残留会话（下次连接将重建全新桌面）
bun run rdp:reset

# 等价 Python 命令
.venv/bin/python scripts/rdp_session_reset.py --node all --check
.venv/bin/python scripts/rdp_session_reset.py --node node0
```

> 判定逻辑：存在 X11 socket（`/tmp/.X11-unix/X*`）但 `gnome-shell` 进程已退出 → 判定为僵死会话。

### 4.4 高速互联口兜底与跳板隧道（管理网失联时）

Node0 与 Node1 之间除 WiFi 外还有一条 **RJ45 物理直连**通道：

| 节点 | 高速口地址 | 网卡 | 对端 |
|---|---|---|---|
| Node0 | `192.168.100.10/24` | `enp1s0f1np1` | Node1 |
| Node1 | `192.168.100.11/24` | `enp1s0f0np0` | Node0 |

该网段**仅在两节点之间直连**，本机（`cube-fe5e`）并无此网卡，因此触达方式如下：

- **SSH 巡检 / 会话重置**：`rdp_session_reset.py` 直连失败后自动经 Node0 建立 `direct-tcpip` 隧道，
  日志会输出「已通过 Node0 跳板建立到 `<ip>` 的隧道」；
- **RDP 连接**：`rdp_connect.py` 在本机 `127.0.0.1:3390` 起监听，经 Node0 转发至远端 `3389`，
  随后客户端连接本地端口即可看到真实桌面。

```bash
# 验证跳板链路（模拟管理网不可达）
NODE1_MGMT_IP=172.19.99.199 .venv/bin/python scripts/rdp_session_reset.py --node node1 --check
# 预期输出：回退到高速互联口 192.168.100.11 → 已通过 Node0 跳板建立隧道 → 巡检正常

# 验证 RDP 转发
.venv/bin/python scripts/rdp_connect.py --node node1 --check
```

> 若 Node0 自身也失联，则高速口通道同样不可用，此时只能到机房本地处理。

## 5. 关键运维配置与注意事项

1. **色彩管理弹窗已免疫（三节点）**：均已配置 `/etc/polkit-1/localauthority/50-local.d/45-allow-colord.pkla`，远程登入后不会弹出「Authentication Required to create a color managed device」授权窗。
2. **Wayland 已禁用（三节点）**：`/etc/gdm3/custom.conf` 中固化 `WaylandEnable=false`，杜绝 Wayland 驱动不兼容导致的无响应。
3. **GDM 自动登录已关闭（三节点）**：本地不再常驻同用户的图形会话，避免与远程 xrdp 会话争抢用户 D-Bus 总线上的 `org.gnome.Shell` / `org.gnome.Mutter.ServiceChannel`（该争抢是 Node123 切换 GNOME 时的关键坑位，详见 §1.1.1）。
4. **连接默认用户**：Node1 的 RDP 默认用户为 **`his_test`**，不再用 `dgxdeploy` 接入（`dgxdeploy` 仅保留给 SSH 运维）；Node0 默认 `winbot`，Node123 默认 `bot`。
5. **SSH 口令与 RDP 口令不同**：Node123 的 SSH 运维口令与 RDP 登录口令是两套凭据，均记录在 `.env`（`SSH_NODE123_PASS` / `NODE123_RDP_PASS`），不可混用。
6. **断开与会话保持**：直接关闭远程桌面窗口，后台会话不会被杀掉；下次重新连入将直接回到未关闭的窗口与终端（实测会话显示号为 `:10`）。
   > ⚠️ 但若客户端被 `SIGTERM` 强杀或网络异常中断，可能留下僵死会话导致黑屏，此时用 `bun run rdp:reset` 清理。
7. **内存保持充裕**：DeepSeek LLM 服务默认开机不自启，两台工作站内存占用仅 3.5～5.0GiB，可用内存超 110GiB。Node123 内存占用更高，主因容器网桥与容器负载（k3s / mysqld），与 RDP 无关。
8. **客户端兼容性**：Linux 下建议使用 FreeRDP 3.x（`xfreerdp3`），Ubuntu 22.04 及更早系统仅有 `xfreerdp` 2.x，参数基本兼容。
   **必须加 `/rfx` + `/bpp:24`**，详见 §3.3。
9. **自签名证书**：服务端使用 `/etc/xrdp/cert.pem` 自签名证书，客户端必须 `/cert:ignore` 或手动信任该证书。
10. **端口前置代理**：本机若配置了 HTTP 代理（如 `http://127.0.0.1:7897`），FreeRDP 会自动读取 `http_proxy` 环境变量，请确保 `172.19.0.0/16` 在 `no_proxy` 白名单内，否则连接会被代理劫持。
11. **多显示器**：建议统一使用 `/dynamic-resolution` 让远程桌面跟随本地窗口尺寸自适应；
    但**老旧 xrdp 服务端除外**（会导致握手失败，见 §3.3）。
12. **不要用 `timeout` 强杀客户端**：`timeout 20 xfreerdp3 ...` 会留下远端僵死会话。如需限时测试，请改用 `--check`（仅巡检）或在测试后执行 `bun run rdp:reset`。
13. **本机桌面为 Wayland**：所有 GUI 客户端在 Wayland 下对 X11 自动化工具不可见，脚本已统一处理。
14. **GNOME 会话切换与验证**：三节点统一为 GNOME Desktop 后，若需调整会话入口，用 `scripts/deploy_gnome_session.py`（支持 `--apply` / `--rollback`），验证用 `scripts/verify_xrdp_real_login.py`（完整复刻 sesman 会话创建链路，无需 RDP 客户端）。
15. **三节点统一 `WN-Office` 热点**：802.1X PEAP 认证，Node1 上其余热点 `autoconnect` 已全部关闭。
    若日后需恢复平铺等窗口管理功能，请勿重新启用系统自带的 `tiling-assistant`（会导致 GNOME Shell 崩溃）。
16. **端口检测不可用裸 TCP**：本机存在 Clash TUN 虚拟网卡，被代理接管的连接会「假性」建立成功，
    导致不存在的地址也被判定为可达。脚本已改用 RDP 协议握手校验（`probe_rdp_service`），
    自定义巡检脚本时务必注意这一点。
17. **`tailscaled` 不要指向本地代理**：Node1 曾因 `tailscaled` 配置了 `127.0.0.1:7890` 而该端口无代理运行，
    导致 Tailscale 掉线。如需代理，请填真实可用地址。

## 6. 故障速查表

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 连接超时无响应 | 网络不通 / 防火墙拦截 | `bun run rdp:check` 查看地址来源；确认 Node1 未漂移到访客网络 |
| **登录成功但黑屏** | **残留僵死会话被复用（`reconnected session`）** | **执行 `bun run rdp:reset` 清理会话后重连** |
| 登录窗后黑屏 | `gnome-shell` 未启动 / Wayland 冲突 | 检查 `~/.xsessionrc` 是否预加载 `ubuntu:GNOME`；确认 `WaylandEnable=false` |
| **登录窗后黑屏（GNOME 会话）** | **`gnome-session` 未指定会话名**：无参 `gnome-session-binary` 不会选中 `ubuntu.session` | **确认 `~/.xsession` 内为 `exec gnome-session --session=ubuntu`；或跑 `scripts/verify_xrdp_real_login.py` 验证** |
| **登录窗后黑屏（GNOME 会话）** | **本地 GDM 自动登录会话争抢 D-Bus 总线名**（`org.gnome.Shell` / `org.gnome.Mutter.ServiceChannel`） | **关闭 `AutomaticLoginEnable=false` 并重启 gdm；`loginctl list-sessions` 确认无同用户本地图形会话** |
| **登录窗后黑屏（GNOME 会话）** | systemd 用户环境注入 `XDG_SESSION_TYPE=tty` | 入口脚本须显式 `export XDG_SESSION_TYPE=x11` 并 `unset WAYLAND_DISPLAY` |
| **登录成功后约 10 秒断开** | **服务端 xrdp 0.9.x 与 FreeRDP 3.x 图形编码协商不兼容** | **客户端追加 `/rfx` + `/bpp:24`，移除 `/dynamic-resolution`** |
| 登录后立刻断开 | 会话脚本报错 | `tail -n 50 /var/log/xrdp-sesman.log` 与 `~/.xsession-errors` |
| 认证失败 | 口令未同步 | `sudo chpasswd` 重置对应用户口令；检查 `/etc/polkit-1/` 与 PAM 规则 |
| 客户端报证书错误 | 服务端自签名证书 | 客户端追加 `/cert:ignore` |
| Remmina 无法连 RDP | 未安装 RDP 协议插件 | `sudo apt install -y remmina-plugin-rdp` |
| Remmina 窗口「抓不到」 | Wayland 会话下 X11 工具不可见 | 脚本已强制 `GDK_BACKEND=x11`；手工启动时同样追加该环境变量 |
| 画面卡顿 / 高延迟 | 未启用动态分辨率或编码 | 追加 `/dynamic-resolution`，降低 `/size` 分辨率 |
| 剪贴板不可用 | 通道未启用 | 客户端追加 `/clipboard` |
| `bun run` 报解释器错误 | 缺少 `.venv` 或 Node.js | 执行 `bun run setup` 建环境；确认 `node -v` 可用 |
| 端口 3389 不通 | 服务未自启 / IP 漂移 | `systemctl is-active xrdp`；检查 Node1 静态 IP 配置 |
| **节点整体失联（ping 不通）** | **WLAN 漂移到访客网络 / 热点认证失败** | `nmcli dev status \| grep wlP9s9`；确认已连接 `WN-Office` 且拿到 `172.19.48.0/22` 段地址 |
| 节点连上但地址是 `172.19.21.x` | 回落到 `WN-Visitor` 访客网络（与管理网隔离） | `sudo nmcli con up "yunshu_WN-Office"`；并关闭访客网络 `autoconnect` |
| Tailscale 显示 offline | `tailscaled` 指向了本地代理但该代理未运行 | `journalctl -u tailscaled \| grep -i proxy`；检查 `override.conf` 的 `HTTP_PROXY` |
| 本机桌面崩溃（signal 6） | `tiling-assistant` 扩展与 mutter 断言冲突 | 已禁用该扩展；如需平铺请装上游新版 Tiling Assistant |
| 端口检测显示「开放」但实际不通 | Clash TUN 代理接管导致 TCP 假阳性 | 用 RDP 协议握手校验；勿用裸 `nc -z` 判断 |
| 高速口地址在本机不通 | `192.168.100.0/24` 仅节点间直连，本机无该网卡 | 走跳板：`bun run rdp:check` 会自动经 Node0 隧道 |

### 6.1 快速诊断决策树

```text
连接失败
├─ 服务探测 FAIL ─────────→ 管理网失联
│   ├─ 看地址来源标注 ─────→ [高速互联口(需跳板)] 说明已自动走 Node0 隧道
│   └─ 仍是 [管理网(不可达)] → 检查热点连接与 Node0 是否在线
└─ 服务探测 PASS
   ├─ 认证失败 ───────────→ 核对 .env 中 NODE*_RDP_PASS / 远端 chpasswd
   ├─ 登录成功但黑屏 ─────→ bun run rdp:reset 后重连（僵死会话）
   ├─ 约 10 秒后断开 ─────→ 客户端加 /rfx + /bpp:24，去掉 /dynamic-resolution
   ├─ 登录窗后黑屏 ───────→ 检查 ~/.xsessionrc 与 WaylandEnable=false
   │                        └─ GNOME 会话专项：scripts/verify_xrdp_real_login.py
   │                           ├─ gnome-session 缺 --session=ubuntu → 修 ~/.xsession
   │                           ├─ 本地自动登录抢总线名 → AutomaticLoginEnable=false + 重启 gdm
   │                           └─ XDG_SESSION_TYPE=tty → 入口显式 export x11
   └─ 画面正常 ────────────→ ✅ 完成
```
