## 1. 架构升级与故障根因解析

在前期测试中，双工作站曾尝试使用 Ubuntu 24.04 的实验性系统级 `gnome-remote-desktop`（Remote Login），但在无物理屏幕（headless）与 NVIDIA GPU 环境下暴露了严重缺陷：
1. **Node0 登录后卡死**：GDM 默认启用 Wayland，无物理显示器时虚拟合成器崩溃；且系统级 RDP 发起的 `Server Redirection` 握手被 Windows 客户端拒绝，导致登录界面挂起。
2. **Node1 无法连接**：Node1 曾因 WiFi 自动跳连至访客网络 `WN-Visitor`，IP 漂移至 `172.19.21.160`，导致网络隔离不可达。

### 现行稳定架构（已全量上线并通过双机重启验证）：
- **底层引擎**：采用工业级成熟稳定的 **`xrdp` + `xorgxrdp`** 架构，监听标准 `3389/tcp` 端口；
- **独立 X11 图形会话**：通过 `/etc/xrdp/startwm.sh` 与 `~/.xsessionrc` 预加载 `ubuntu:GNOME` 完整桌面环境，绕过脆弱的 Wayland 重定向机制，直接进入桌面；
- **网络固化**：Node1 已锁死静态 IP `172.19.49.159/22`（网关 `172.19.51.254`），彻底禁用访客网络自连；
- **双机重启验证**：两台工作站已完成全新重启自检，系统开机自启 `xrdp`、`xrdp-sesman` 与 `ssh` 服务，LLM 模型未自动启动，可用内存保持在 114～118GiB。

## 3. 本机（Windows）直连操作流程

### 3.1 方式一：双击预设 `.rdp` 快捷方式（推荐）

项目 `scripts/` 目录下已预置专用的 Windows 远程桌面连接文件：

1. **连接工作站 Node0**：
   - 快捷文件：[`scripts/工作站_Node0_172.19.50.70.rdp`](file:///e:/work/mydgx/scripts/工作站_Node0_172.19.50.70.rdp)
   - 双击打开，在 xrdp 登录窗（Session: Xorg）确认用户名为 `winbot`，输入密码 `winbot`，按回车即可进入桌面。
2. **连接工作站 Node1**：
   - 快捷文件：[`scripts/工作站_Node1_172.19.49.159.rdp`](file:///e:/work/mydgx/scripts/工作站_Node1_172.19.49.159.rdp)
   - 双击打开，确认用户名为 `dgxdeploy`（或 `his_test`），输入密码 `winning`，按回车即可进入桌面。

### 3.2 方式二：使用 Windows 自带 `mstsc` 客户端

1. 快捷键 `Win + R` 调出运行窗口，输入 `mstsc` 并回车；
2. 输入计算机地址：
   - Node0：`172.19.50.70`
   - Node1：`172.19.49.159`
3. 弹出登录窗口后，Session 选择默认的 `Xorg`，输入对应账号密码登录；
4. 成功登录后即可直接进行终端、浏览器、文件管理器等全部图形化桌面操作。

## 4. 自动化运维与巡检工具

所有运维脚本均采用纯 **Python 3** 编写，位于项目的 [`scripts/`](file:///e:/work/mydgx/scripts/) 目录，基于项目独立的虚拟环境 `.venv/`：

### 4.1 状态巡检命令
```bash
# 巡检双机 xrdp 服务状态与 3389 连通性
bun run rdp:status
# 或直接调用 Python 脚本：
.venv\Scripts\python.exe scripts/verify_all_after_reboot.py
```

### 4.2 重新部署与一键修复
如遇环境变更或需要重新部署 xrdp 配置，可执行：
```bash
.venv\Scripts\python.exe scripts/deploy_robust_rdp.py
```

## 5. 关键运维配置与注意事项

1. **色彩管理弹窗已免疫**：
   已配置 `/etc/polkit-1/localauthority/50-local.d/45-allow-colord.pkla`，远程登入桌面后不会弹出烦人的「Authentication Required to create a color managed device」授权窗口。
2. **Wayland 已禁用**：
   `/etc/gdm3/custom.conf` 中已固化 `WaylandEnable=false`，杜绝因 Wayland 驱动不兼容导致的无响应。
3. **断开与会话保持**：
   直接关闭远程桌面窗口，后台会话不会被杀掉；下次重新连入时将直接回到当前未关闭的窗口与终端。
4. **内存保持充裕**：
   DeepSeek LLM 大模型服务已配置默认开机不自启，两台工作站内存占用仅 3.5～5.0GiB，可用内存超 110GiB，图形桌面操作极其丝滑顺畅。
