## 1. 架构说明与历史故障根因

前期测试曾采用 Ubuntu 24.04 的实验性系统级 `gnome-remote-desktop`（Remote Login），在无物理屏幕（headless）与 NVIDIA GPU 环境下暴露了严重缺陷：

1. **Node0 登录后卡死**：GDM 默认启用 Wayland，无物理显示器时虚拟合成器崩溃；系统级 RDP 发起的 `Server Redirection` 握手被 Windows 客户端拒绝，导致登录界面挂起。
2. **Node1 无法连接**：Node1 曾因 WiFi 自动跳连访客网络 `WN-Visitor`，IP 漂移至 `172.19.21.160`，造成网络隔离不可达。

### 现行稳定架构（已全量上线并通过双机重启验证）

- **底层引擎**：工业级成熟稳定的 **`xrdp` + `xorgxrdp`** 架构，监听标准 `3389/tcp`；
- **独立 X11 图形会话**：通过 `/etc/xrdp/startwm.sh` 与 `~/.xsessionrc` 预加载 `ubuntu:GNOME` 完整桌面环境，绕过脆弱的 Wayland 重定向机制；
- **网络固化**：Node1 已锁死静态 IP `172.19.49.159/22`（网关 `172.19.51.254`），彻底禁用访客网络自连；
- **开机自启**：`xrdp`、`xrdp-sesman` 与 `ssh` 服务随系统自启，LLM 模型默认不自启，可用内存保持 114～118GiB。

## 3. 跨平台连接方式

### 3.1 统一入口（推荐，三平台通用）

项目提供统一连接脚本 [`scripts/rdp_connect.py`](file:///home/bot/work/mydgx/scripts/rdp_connect.py)，自动探测本机可用客户端并完成连接。

```bash
# 0) 首次准备虚拟环境（等价于 bun run setup）
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 1) 查看本机可用的 RDP 客户端与节点清单
.venv/bin/python scripts/rdp_connect.py --list

# 2) 仅巡检（端口连通性 + 远端 xrdp 服务状态）
.venv/bin/python scripts/rdp_connect.py --node all --check

# 3) 连接双机（自动按 freerdp → remmina → rdesktop → mstsc 顺序选客户端）
.venv/bin/python scripts/rdp_connect.py --node all

# 4) 指定节点 / 分辨率 / 客户端
.venv/bin/python scripts/rdp_connect.py --node node0 --size 1920x1080
.venv/bin/python scripts/rdp_connect.py --node node1 --client freerdp

# 5) 仅生成连接描述文件，不发起连接
.venv/bin/python scripts/rdp_connect.py --node all --generate
```

> 脚本会先做 `3389` 端口预检与 SSH 远端巡检，不可达时自动跳过连接，避免长时间挂起。
> Windows 下请将解释器换为 `.venv\Scripts\python.exe`，路径分隔符同理。

### 3.2 快捷命令（bun / npm，三平台通用）

项目在 `package.json` 中注册了跨平台快捷入口，可直接使用 `bun run` 或 `npm run` 调用：

| 命令 | 等价 Python 命令 | 说明 |
|---|---|---|
| **`bun run server70`** | `rdp_connect.py --node node0` | **连接工作站 Node0（`172.19.50.70`）** |
| **`bun run server159`** | `rdp_connect.py --node node1` | **连接工作站 Node1（`172.19.49.159`）** |
| `bun run rdp:connect` | `rdp_connect.py --node all` | 依次连接双机 |
| `bun run rdp:check` | `rdp_connect.py --node all --check` | 仅巡检，不发起连接 |
| `bun run rdp:generate` | `rdp_connect.py --node all --generate` | 仅生成 `.rdp` / `.remmina` 连接描述文件 |
| `bun run rdp:clients` | `rdp_connect.py --list` | 列出本机可用客户端与节点清单 |
| `bun run rdp:status` | `setup_rdp.py --status` | 双机 RDP 部署态详细巡检 |
| `bun run rdp:diagnose` | `diagnose_rdp.py` | 登录卡死等故障诊断 |
| `bun run setup` | — | 创建 `.venv` 并安装 `requirements.txt` 依赖 |

```bash
# 实际使用示例
bun run server70                    # 连接 Node0
bun run server159                   # 连接 Node1
bun run server70 --size 1920x1080  # 追加参数透传给底层 Python 脚本
bun run server159 --check           # 只做连通性巡检
```

> **参数透传机制**：快捷命令通过 [`scripts/py_run.mjs`](file:///home/bot/work/mydgx/scripts/py_run.mjs) 转发，
> 该启动器按 `.venv` → `PYTHON` 环境变量 → 系统 `python3`/`python` 的优先级自动解析解释器，
> 并将 `--size`、`--client`、`--check` 等附加参数原样透传给 `scripts/rdp_connect.py`。
> 因此在 Linux / macOS / Windows 上使用同一条命令均可正常工作。

### 3.3 Linux（本机推荐 FreeRDP）

**安装客户端：**

```bash
# 方式 A：系统包（需 sudo）
sudo apt install -y freerdp2-x11        # 提供 xfreerdp / xfreerdp3
sudo apt install -y remmina             # 图形化客户端

# 方式 B：无 root 权限时使用项目内便携版（已预置 .cache_packages/freerdp）
# 脚本会自动发现该目录并注入 LD_LIBRARY_PATH
```

**手工连接命令：**

```bash
# FreeRDP 3.x
xfreerdp3 /v:172.19.50.70:3389 /u:winbot /p:****** \
          /cert:ignore /size:1920x1080 /dynamic-resolution /clipboard /sound

# FreeRDP 2.x（Ubuntu 22.04 及更早）
xfreerdp /v:172.19.50.70:3389 /u:winbot /p:****** \
         /cert:ignore /size:1920x1080 /dynamic-resolution /clipboard
```

> `/cert:ignore` 用于跳过自签名证书校验，**仅适用于内网可信环境**。
> 若需剪贴板、声音、磁盘重定向，请显式追加 `/clipboard`、`/sound`、`/drive:shared,/media`。

**Remmina 图形化方式：**

1. `sudo apt install -y remmina`，启动后在「Remmina → RDP」中新建连接；
2. 或直接双击项目已生成的配置：[`scripts/工作站_Node0_172.19.50.70.remmina`](file:///home/bot/work/mydgx/scripts/工作站_Node0_172.19.50.70.remmina)、[`scripts/工作站_Node1_172.19.49.159.remmina`](file:///home/bot/work/mydgx/scripts/工作站_Node1_172.19.49.159.remmina)。

## 5. 关键运维配置与注意事项

1. **色彩管理弹窗已免疫**：已配置 `/etc/polkit-1/localauthority/50-local.d/45-allow-colord.pkla`，远程登入后不会弹出「Authentication Required to create a color managed device」授权窗。
2. **Wayland 已禁用**：`/etc/gdm3/custom.conf` 中固化 `WaylandEnable=false`，杜绝 Wayland 驱动不兼容导致的无响应。
3. **断开与会话保持**：直接关闭远程桌面窗口，后台会话不会被杀掉；下次重新连入将直接回到未关闭的窗口与终端（实测会话显示号为 `:10`）。
4. **内存保持充裕**：DeepSeek LLM 服务默认开机不自启，两台工作站内存占用仅 3.5～5.0GiB，可用内存超 110GiB。
5. **客户端兼容性**：Linux 下建议使用 FreeRDP 3.x（`xfreerdp3`），Ubuntu 22.04 及更早系统仅有 `xfreerdp` 2.x，参数基本兼容。
6. **自签名证书**：服务端使用 `/etc/xrdp/cert.pem` 自签名证书，客户端必须 `/cert:ignore` 或手动信任该证书。
7. **端口前置代理**：本机若配置了 HTTP 代理（如 `http://127.0.0.1:7897`），FreeRDP 会自动读取 `http_proxy` 环境变量，请确保 `172.19.0.0/16` 在 `no_proxy` 白名单内，否则连接会被代理劫持。
8. **多显示器**：跨平台建议统一使用 `/dynamic-resolution`，让远程桌面跟随本地窗口尺寸自适应。

## 6. 故障速查表

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 连接超时无响应 | 网络不通 / 防火墙拦截 | `nc -vz 172.19.50.70 3389` 验证；确认 Node1 未漂移到访客网络 |
| 登录窗后黑屏 | `gnome-shell` 未启动 / Wayland 冲突 | 检查 `~/.xsessionrc` 是否预加载 `ubuntu:GNOME`；确认 `WaylandEnable=false` |
| 登录后立刻断开 | 会话脚本报错 | `tail -n 50 /var/log/xrdp-sesman.log` 与 `~/.xsession-errors` |
| 认证失败 | 口令未同步 | `sudo chpasswd` 重置对应用户口令；检查 `/etc/polkit-1/` 与 PAM 规则 |
| 客户端报证书错误 | 服务端自签名证书 | 客户端追加 `/cert:ignore` |
| 画面卡顿 / 高延迟 | 未启用动态分辨率或编码 | 追加 `/dynamic-resolution`，降低 `/size` 分辨率 |
| 剪贴板不可用 | 通道未启用 | 客户端追加 `/clipboard` |
